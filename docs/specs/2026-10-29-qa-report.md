# The QA report

Status: accepted, built in one pull request. [validation.md](../methodology/validation.md) says what the QA report is for: every build writes `qa.md` into its bundle, a build with a failing check is not published, and the report shows coverage, ranges, nulls, the result of every check and the changes since the previous build. This spec says what it holds and how it works.

## What it is

`atlas qa <region>` reads a built bundle (`manifest.json` and `cells.parquet`) and writes `qa.md` beside them. `atlas build` runs the same code on the bundle it has just written. It reads only the bundle and the catalogue, never the raw downloads, so it can be run again on any build, in seconds, and the same code serves every region.

A check has one of four results:

- **pass**
- **warn**: shown in the report and in the build's summary, and does not stop publishing
- **fail**: stops publishing
- **skipped**: the bundle lacks an indicator that the check reads (a commercial build leaves some out)

## The checks

| Group | Fails when | Warns when |
| --- | --- | --- |
| The bundle | The rows differ from the manifest's `cell_count`; the cells are not sorted and unique, or are not H3 cells of the grid's resolution; a column of the manifest is not in the table, or a column of the table is not in the manifest; a neighbourhood number is outside the list | |
| Datasets | An indicator cites a dataset that the manifest lacks; a dataset has no attribution | A dataset's licence is `unknown` |
| Values, for each indicator | A value is infinite or below zero; a percentage is above 100; an index is outside 0 to 1; a text value is one that the indicator's lookup curve cannot score; no cell has a value | Fewer than half of the cells have a value; every valued cell has the same value |
| Relations | Two independent datasets that should agree do not: the rank correlation (Spearman's) has the wrong sign or falls short of the relation's floor | |
| Known facts | A fact that anyone can verify does not hold in the data | |

Each dataset's `commercial_use` marking is listed in the report but is not a warning: D07 makes the build non-commercial for now, and a warning that never goes away is noise.

## The report

1. **The result** in one line, with the bundle's version and its numbers of cells, indicators and checks.
2. **What needs a look**: each failure and warning, with its detail. Empty when there are none.
3. **Data by indicator**: the unit, the share of cells with a value, and the lowest, 5th percentile, median, 95th percentile and highest value, then the share of valued cells at full marks and at no marks on the indicator's curve (a ramp or an ideal range), so that a curve that gives nearly every cell the same score shows. A text indicator (the service level, the fare zone) shows the share of cells in each category with its score. The options of a choice indicator are listed in the same way under it.
4. **Factors**: for each top-level factor, the share of cells that it can score, and the average share of its weight (the default weights) that has data, with the share of cells under the engine's 70% flag.
5. **Datasets**: licence, commercial use, date and attribution of each dataset in the bundle.
6. **Relations** and **Known facts**: each with its result and the numbers behind it.
7. **Changes since the previous build**: indicators added or removed, a coverage that moved by a point or more, a median that moved by 5% or more, a dataset added, removed or re-dated, and the cell count. Or "No change".

The report carries no date or time, so the same bundle gives the same report. It is written after the bundle's version is fixed and is not part of the version's hash.

## Publishing

`latest.json` is the pointer that the web app follows, and it is the act of publishing. The build writes the bundle's folder first, then the report, and moves the pointer only if no check failed. A failed build exits with an error that lists the failures and the version, and leaves the previous pointer where it was. `atlas qa <region> --version <v> --publish` checks a bundle again and publishes it if it passes, which saves a nine-minute rebuild after a check or a fact has been corrected. `latest.json` also records the version it replaced as `previous`, which the report compares against; the web app reads only `version`.

## Known facts and relations

They are about one region, so they live with its datasets, in `datasets/cities/<region>/facts.py`, and a region without such a file has none. A fact is a function that reads the bundle through named places (Soho, Wimbledon village) and either returns the numbers it found or says what is wrong. The facts that were tests in `test_known_facts.py` moved there, and that test now runs each of them. A relation names two columns, the sign that their rank correlation should have, a floor for its strength and the reason.

Facts stay as code and not as a data file: they mix comparisons between places, medians, orderings and sums over a group of columns, and a data format that covers those would be a language of its own. If a second city shows the shapes that repeat, they can move to the catalogue then.

## Decisions to review

- **The floors of the relations** are set from the reason a relation should hold, well under the strength seen in London's data (shown beside each relation in the report), so only a broken input trips them. Observed on the build of 29 October: station walk and service level −0.73, station walk and rail lines −0.82, service level and bus routes +0.80, NO₂ and road noise +0.49, price and rent per borough +0.68, travel time and service level −0.67, A&E distance and travel time +0.46, cafés and the walk to a station −0.67, diversity and share born in the UK −0.86 (two census tables), the walk to a mosque and the share of Muslim residents −0.57 (OpenStreetMap against the census).
- **A licence of `unknown` is a warning, not a failure**, because D07 lets the non-commercial build use it and the owner has the open question. It shows for the LAEI until that is settled.
- **A build that fails is kept on disk and not published**, so its report can be read.

## Out of scope

- Checks that reproduce a dataset from the raw files (crime counts per borough against Police.uk's totals) need the raw data. They belong to the indicators' own tests.
- Outside comparisons with published rankings (Phase 2, "why we differ").
- That `just build london` gives the same bundle twice on the real data: the version is a hash of the content, which a test pins on synthetic data. The real rebuild is run and recorded in the progress log, not in the report.
